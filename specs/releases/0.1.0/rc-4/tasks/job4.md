## Task notes

- **J4.T1.** Fixtures: `proving-post` (lang `pt`, date `2026-03-09`, tags `data, notes`, `image: shot.png`; body holds a heading, a paragraph, an `http(s)` link, a site-relative link, a `#` link, a line `<script>alert(1)</script>`, a fenced block holding `a < b`, `![alt text](shot.png)` and `![clip alt](clip.mp4)`); `second-post` (lang `en`, date `2026-02-01`, tags `notes`, no media); `draft-post` (`draft: true`). `shot.png` and `clip.png` are valid PNGs of a few pixels with different sizes; `clip.mp4` is a placeholder file, never decoded. Asserts, all literal: `readPosts` returns `proving-post` then `second-post`, none for the draft; the fields of each; an absent directory gives `[]`. One temp post per failure, each expecting the exact message `<slug>: <field>: <message>` of PLAN §2.2 (blank title, bad date, bad lang, unknown key, missing field, bad tags, `draft: maybe`, `image` naming no file, slug with an upper-case letter, folder without `index.md`, a line that is not `key: value`). A draft with a bad field fails too: drafts are validated, then filtered.
- **J4.T2.** One front-matter parser, one zod strict object, one `readPosts`; `vite.config.ts` (Job 7) and the script both import it, which makes it the one decider of "published". It imports `zod` and `node:fs` only, so the Vite config can load it.
- **J4.T3 and J4.T4.** `build-blog.mjs`: CLI `node scripts/build-blog.mjs [--posts <dir>] [--dist <dir>]` (defaults `content/blog`, `dist`, cwd `frontend/`), guarded so importing it runs nothing. It writes `<dist>/blog/index.json` (`[]` with no post) and, per post, `<dist>/blog/<slug>/body.html`. The renderer is a `marked` instance with three overrides: raw HTML tokens render as escaped text; a link is kept only if `HttpUrl` (imported from `../src/lib/schemas/projects.ts`, as `content-schema.mjs` does) accepts it, or it starts with a single `/`, or with `#`, else the build fails with `<slug>: link: "<href>" is not http(s), site-relative or #`; a code block is `<pre><code>` plus escaped text with no language class. Tests: stdout, stderr and exit code of `execFileSync(process.execPath, ["scripts/build-blog.mjs", ...])` against a temp `dist`; the `javascript:` and `mailto:` and bare-relative links are temp posts that must fail; `<script>` in the proving post must come out as `&lt;script&gt;alert(1)&lt;/script&gt;`. `package.json`: `"build": "vite build && node scripts/build-blog.mjs"`, `marked` under `devDependencies` at the newest 18.x (`npm view marked version`; MIT, no dependencies, Node 20 or newer), the lock regenerated with `npm install --package-lock-only`, `npm ci` green. The hand-back reports `npm audit` for the new package (0 expected) and the build times above.
- **J4.T5 and J4.T6.** `imageSize(file)` returns `{ width, height }` for `png` (IHDR), `jpg` (first SOF marker), `webp` (`VP8 `, `VP8L` and `VP8X` chunks) and `svg` (`width` and `height` attributes in px, else `viewBox`); any other extension or an unreadable header throws a message naming the file. The test writes minimal header bytes inline per format; no new binary fixture. Job 5 imports it to check the share image, so it is one module, not a helper inside the script.
- **J4.T7 and J4.T8.** An image `![alt](shot.png)` becomes `<img src="/blog/<slug>/shot.png" alt="alt text" width="W" height="H">`. A clip becomes `<video aria-label="clip alt" width="W" height="H" poster="/blog/<slug>/clip.png" muted loop playsinline controls preload="none"><source src="/blog/<slug>/clip.mp4" type="video/mp4"></video>`, `video/webm` for `.webm`, with no `autoplay` attribute; the poster is the file of the same base name beside the clip (first of `webp`, `png`, `jpg`) and gives the size. Sources are absolute from the site root because a post is served at `/blog/<slug>` with no trailing slash, so a bare name would resolve against `/blog/`. Every referenced file, the poster and the front-matter `image` are copied byte-for-byte to `<dist>/blog/<slug>/` under their own names; `index.md` and unreferenced files are not. Failures: empty alt `<slug>: image: alt must not be empty`; missing file `<slug>: image: shot.png: no such file`; clip without poster `<slug>: video: clip.mp4: no poster beside it`; any image target that is not a file of the post folder with a `png`, `jpg`, `webp` or `svg` extension (clips: `mp4`, `webm`) fails the same way. The tests assert the literal tag text, the copied bytes, and that `autoplay` appears nowhere.
