The handler returns the request object. A path whose last segment holds a dot is unchanged even with a trailing slash. The file loads and runs with no other global.
- **J2.T2.** `viewer-request.js` is ES5-style (`function handler(event)`, no module syntax) for the `cloudfront-js-2.0` runtime: drop one trailing slash; if the path is `/` or its last segment holds a `.`, return the request untouched; else append `/index.html`. `cloudfront.tf` gains `resource "aws_cloudfront_function" "rewrite"` (`name = "${replace(local.domain, ".", "-")}-rewrite"`, `runtime = "cloudfront-js-2.0"`, `publish = true`, `code = file("${path.module}/viewer-request.js")`) and, inside `default_cache_behavior`, `function_association { event_type = "viewer-request"; function_arn = aws_cloudfront_function.rewrite.arn }`, one attribute per line. The custom error responses (403 and 404 to the root document with 200) are unchanged: AC1.1's "no file falls through" relies on them. `terraform.yml`'s `Format check` runs on the PR and no terraform runs locally, so align every `=` by hand as `terraform fmt` does (consecutive attributes of one block share a column); the reviewer reads the alignment. No `iam.tf` change: PLAN §2.5 states the role question.
- **J2.T3.** In `deploy-stage` and `deploy-prod`, the step `Sync static assets to S3 (long-lived cache)` and the step `Upload index.html (no-cache)` are replaced by two steps, assets first, each with `--delete` and the existing `--exact-timestamps`:
  - `aws s3 sync dist/ s3://<bucket> --delete --exact-timestamps --exclude "*" --include "assets/*" --cache-control "public, max-age=31536000, immutable"`;
  - `aws s3 sync dist/ s3://<bucket> --delete --exact-timestamps --exclude "assets/*" --cache-control "no-cache"`.

  Why this is safe, from the AWS CLI reference (cited in PLAN §2.5): a later filter overrides an earlier one, `*` matches every key including `/`, and "files excluded by filters are excluded from deletion". So each sync deletes only inside its own set and neither can delete the other's objects. A removed post's HTML is deleted by the second sync. The invalidation, the `if:`, the secrets and the build job are untouched. The commit body states that both jobs carry the same two steps.
