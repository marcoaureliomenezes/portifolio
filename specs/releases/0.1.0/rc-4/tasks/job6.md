## Task notes

- **J6.T1.** `test-setup.ts` gains one branch beside the locale one: `/blog/index.json` answers `[]` with a JSON content type, so every test without posts gets the empty index (pre-mortem hit 62, B10). Tests that need posts layer their own `fetch` over it. Index asserts, literal, over two inline posts (`lang` `pt` and `en`, the `pt` one newer): both listed in pt, en and de, newest first; each shows its title as a link to `/blog/<slug>`, its description, its tags, its date as `9 de março de 2026`, `March 9, 2026`, `9. März 2026` for `2026-03-09` in pt, en, de, and a language tag whose text is `PT` or `EN`, carrying `lang="pt"` or `lang="en"`. `/blog?tag=notes` lists only the posts tagged `notes`; `/blog?tag=nope` lists none and shows `siteChrome.blog.empty`; the filter shows `filteredBy` with the tag and an `allPosts` link to `/blog`; each tag chip links to `/blog?tag=<tag>`. An empty or failing index shows `blog.empty`.
- **J6.T2.** `BlogPostPage`: for a slug in the index it shows the title (h1), the date, the language tag, the tags and the fetched `body.html` inside `<article lang="<post lang>">`, with a `back` link to `/blog`; `useDocumentSeo` sets `document.title` to the post title and the description meta to its description. An unknown slug, or a failing `body.html`, renders `NotFound`. `blogRoutes.test.tsx` renders `App` at `/blog` (empty index) and `/blog/some-post` (404 content) after `window.history.pushState`, proving both routes exist whether or not a post exists.
- **J6.T3.** `lib/blogIndex.ts` holds the `BlogPost` type (`slug`, `title`, `description`, `date`, `lang`, `tags`, as Job 4 writes them) and `useBlogIndex()`: it fetches `/blog/index.json` with `cache: "no-cache"` (as `LanguageContext.tsx:42` does for the locale files) and returns the posts, or `[]` on any failure. `PostMeta` renders date (`Intl.DateTimeFormat(language, { dateStyle: "long", timeZone: "UTC" })` over the `YYYY-MM-DD` read as UTC), the language tag and the tag chips; both pages use it. The index page sets `useDocumentSeo` from `blog.title` and `blog.intro`, uses the h1 shape of `ProjectsIndexPage`, and filters on the `tag` search param client-side.
- **J6.T4.** `BlogPostPage` renders the fetched fragment with `dangerouslySetInnerHTML`; this is safe only because the build escapes raw HTML and limits link schemes (AC2.3), and the commit body says so. `App.tsx` adds `/blog` and `/blog/:slug` as `lazy` routes under `SiteLayout`, beside the projects group and outside `ProjectsLayoutShell`, with the same `lazy(() => import(...).then(...))` form as the projects pages.
