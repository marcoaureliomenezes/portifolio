Última atualização: 2026-05-17 · Derivado de: specs/foundation/SPEC.md, reports do ciclo de Retomada 2.0.

Visão arquitetural

Portfólio 2.0 é um SPA estático servido por CloudFront, com camada futura de escrita serverless (CMS-lite P1). Sem servidor de aplicação em produção. Toda renderização é client-side a partir do index.html + assets hashed; conteúdo (textos/listas) é JSON estático lido em runtime via hook useContent().

Regras de fronteira

  1. Frontend nunca chama AWS direto. Toda escrita (P1) passa por API Gateway + Lambda. Leitura pública é via CloudFront sobre S3 (OAC).
  2. Lambda nunca lê fora do prefix content/*. Permissão IAM mínima: s3:PutObject em arn:aws:s3:::<bucket>/content/*. Sem s3:GetObject no Lambda — leitura é responsabilidade do CloudFront.
  3. Hook useContent() é o único ponto de carga de conteúdo. Componentes recebem labels localizados; não importam getContent diretamente. Isso habilita F-P0-06 e F-P1-01 sem refator em cada consumidor.
  4. Fallback de idioma: useContent() resolve para en quando chave faltar em de. Nunca para pt.
  5. Roteamento por rotas, não por tabs de UI. Abas de projeto são rotas (/projetos/<slug>) — deep-linkáveis, SEO-friendly, sem dependência do componente Tabs do shadcn.
  6. Estado de UI fica no componente que possui a interação. RoleCollapsible mantém seu próprio open; orquestrador Portfolio é stateless.
  7. Variantes desktop/mobile: 1 componente + Tailwind responsive utilities (md:*), não dois componentes duplicados. useIsMobile() apenas para casos onde DOM precisa ser estruturalmente diferente.

Princípios SOLID aplicáveis

  • S (SRP): corrigido pela decomposição. God-component Portfolio.tsx foi violação CRITICAL do AS-IS — resolvida.
  • O (OCP): getProviderIcon / getSkillIcon (switches por string) viram mapas declarativos em data/content/<lang>.json ou em constantes nomeadas. Adicionar 5ª seção não exige tocar no orquestrador.
  • D (DIP): useContent() abstrai a fonte (.ts constants -> JSON -> CMS endpoint). Único ponto de troca.

Anti-patterns proibidos

  • God Component — qualquer componente > 250 linhas deve ser decomposto.
  • Prop Drilling de language — proibido. Usar LanguageContext ou useContent().
  • Speculative Generality — não instalar libs "por precaução" (lição @tanstack/react-query montado sem uso).
  • Magic Strings — language === "Português" proibido. Usar tipo discriminado SupportedLanguages = "pt" | "en" | "de".
  • Modais sem Radix Dialog — proibido. Sempre dialog.tsx (focus trap + ARIA + ESC).

Invariantes arquiteturais

  1. Sem servidor de aplicação em produção — apenas SPA estático sobre CloudFront/S3.
  2. Sem credenciais AWS de longo prazo no DEV local — todo apply/sync via GitHub Actions OIDC (CT-01..CT-04 em specs/SPEC.md §4b).
  3. Todo conteúdo localizável vive em JSON, não em .ts constants — única exceção são URLs e enums em data/profile.ts.
  4. Hook useContent() é o único ponto de entrada de conteúdo — DIP enforced.
  5. Fallback de idioma é determinístico: de faltante -> en, nunca pt.
  6. Toda página com lógica condicional real tem unit test colocado (Vitest+RTL); toda página pública tem cenário E2E (Playwright) + smoke axe.
